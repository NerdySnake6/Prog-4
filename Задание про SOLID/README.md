# Реализация принципа единственной ответственности (Single Responsibility Principle - SRP)

## Описание принципа
Принцип единственной ответственности (SRP) гласит: каждый класс должен решать ровно одну задачу. У класса должна быть только одна причина для изменения. Нарушение этого принципа приводит к сильной связанности кода, усложняет тестирование и поддержку.

## Предметная область
В качестве примера выбрана предметная область автоматизации алхимической лаборатории (учет рецептов зелий и расчет стоимости их производства).

## Нарушение принципа (До исправления)
В исходной реализации класс `AlchemistViolation` (в файле [srp_violation.py](file:///Users/nerdysnake6/Documents/Prog-4/%D0%97%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%BF%D1%80%D0%BE%20SOLID/srp_violation.py)) совмещает три разные зоны ответственности:
1. **Логика приготовления зелий** — смешивание ингредиентов.
2. **Работа с базой данных или файловой системой** — запись рецепта в текстовый файл `grimoire.txt`.
3. **Финансовые расчеты** — вычисление стоимости зелья с учетом налоговой ставки.

**Недостатки текущей реализации:**
* Изменение способа хранения данных (например, переход на JSON или SQL базу данных) потребует редактирования логики алхимика.
* Изменение налоговой ставки или правил ценообразования также затронет класс алхимика.

## Решение проблемы (После исправления)
В исправленной версии (в файле [srp_solution.py](file:///Users/nerdysnake6/Documents/Prog-4/%D0%97%D0%B0%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5%20%D0%BF%D1%80%D0%BE%20SOLID/srp_solution.py)) обязанности разделены между независимыми классами:
1. **`Potion`** — структура данных, содержащая информацию о зелье.
2. **`Alchemist`** — класс, отвечающий исключительно за приготовление зелий.
3. **`GrimoireRepository`** — класс, управляющий хранением и записью рецептов.
4. **`PotionPricingCalculator`** — калькулятор стоимости, содержащий формулы финансового расчета.

**Преимущества исправленной версии:**
* **Изолированность:** изменения в правилах ценообразования или механизме сохранения файлов локализованы в соответствующих модулях и не затрагивают основной класс `Alchemist`.
* **Тестируемость:** каждый класс теперь можно протестировать независимо.
